# Implementation Plan: Olympia BoD Analyzer MVP Comparison Core

**Branch**: `001-olympia-bod-analyzer` | **Date**: 2025-10-10 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `/specs/001-olympia-bod-analyzer/spec.md`

## Summary

Deliver an on-premise analysis workflow that ingests two consecutive Olympia BoD decks, extracts and aligns text, tables, and screenshots, highlights variances across financial, commitment, tone, and omission dimensions, generates evidence-backed narratives, and exports an executive brief—all within the 15-minute review window mandated by the constitution.

## Technical Context

**Language/Version**: Python 3.11 (backend), TypeScript with React 18 (frontend)  
**Primary Dependencies**: FastAPI, PyMuPDF, pdfplumber, Tesseract OCR, layoutparser, sentence-transformers, OpenAI GPT-4 Turbo plus secondary OpenAI endpoint for failover, React, Tailwind CSS, Playwright (confirmed E2E harness)  
**Storage**: SQLite for structured outputs and run metadata;
**Testing**: Pytest (unit/integration), Jest + React Testing Library (component), Playwright for end-to-end regression of analyst flow, bespoke accuracy regression harness for extraction/diff modules  
**Target Platform**: Dockerized deployment on Olympia-controlled Linux servers (CPU-first, GPU optional)  
**Project Type**: Web application with decoupled FastAPI backend and React/Tailwind frontend, plus shared schema workspace  
**Performance Goals**: ≤15 minutes end-to-end deck comparison for two 100-page PDFs; ≤3s p95 for dashboard interactions; ≤30s export brief generation; observability to surface accuracy %, latency p95, and deletion audit events  
**Constraints**: Zero external telemetry; clickable “Slide X” citations must deep-link to evidence; commitment/tone outputs require confidence ≥0.95 or manual flag; automatic fallback to secondary OpenAI model when GPT-4 endpoint unavailable  
**Scale/Scope**: Single deck pair per session (up to ~100 slides each); pilot cohort ≤10 concurrent analyst sessions; unlimited PDF file size constrained only by local storage capacity planning

## Phase 0 — Research & Clarifications

1. **Privacy Impact & Storage Plan**: storage sizing strategy given unlimited PDF file policy, encryption controls, and auditable manual deletion workflow. Document controls and verification steps in `research.md`.
2. **OCR & Bilingual Pipeline Assurance**: Benchmark PyMuPDF + Tesseract + layoutparser on decks; capture fallback accuracy thresholds, remediation plan, and required tuning assets.
3. **Citation Deep-Link Strategy**: Define how “Slide X” links map to precise deck coordinates across dashboard and offline briefs, including data structures and UI expectations.
4. **GPT-4 Failover Playbook**: Evaluate secondary OpenAI endpoint/model options, configuration management, latency impact, and operational safeguards for automatic switchover.
5. **Embedding & Alignment Model Selection**: Compare sentence-transformer variants tuned for BoD content; record rationale, benchmarks, and retraining cadence.
6. **Observability & Accuracy Metrics Design**: Establish instrumentation strategy for accuracy percentages, latency p95 sampling, commitment/tone confidence distributions, and deletion audit logs while avoiding raw deck storage.
7. **End-to-End Harness Validation**: Finalize Playwright scenarios, coverage scope, and maintenance expectations for cross-stack smoke tests.

*Deliverable*: `research.md` summarizing each decision with rationale and alternatives (≤3 open questions allowed, none blocking constitution gates).
